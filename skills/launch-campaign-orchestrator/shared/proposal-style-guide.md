# Proposal Voice & Taste Guide

This file is **not** a style template. It's a **taste contract** — a list of qualities a good strategic proposal exhibits, regardless of what shape AI chooses for the deck. Use this guide to check the **voice** of what you write, not its **form**.

> **Why this is not a style template:**
> A previous version codified specific surface forms (双层页眉、L1-L5 口号化分级、SWOT 四列、痛点-卖点表格、传播标题前置、视觉注解块、章末小结、营销回顾页). Those are forms one specific reference deck used. Forcing them onto every proposal would produce template-党 surfaces. Instead, this guide describes **what good taste looks like**, leaving form free.

## The Eight Qualities of a Good Proposal Voice

A strategic proposal that procurement evaluators remember exhibits most of the following qualities. AI is expected to **bring** these qualities into whatever shape it chose, not to manufacture artifacts that nominally satisfy them.

### Quality 1 · 人话洞察 (Insight in Human Speech)

Data and tables are necessary; they're not sufficient. After every key data block, evaluators need a **one-sentence insight in plain Chinese** — not a footnote, not buried in copy. The sentence should be quotable in a meeting room.

- 不允许：表格之后只接下一个表格 / 只用"由此可见"过渡
- 期望：表格 → 一句"赛道增速持续领跑，溢价显著"或"这意味着 {target_audience} 已经准备好换车，但他们在等一个理由"

### Quality 2 · 痛点闭环 (Pain-Point Closure)

每一个产品**核心卖点**必须能找到一个客群**痛点**与之对应，反过来每一个被识别的痛点也要有产品答案；同时这个对应必须在**至少一个具体活动 / 一个具体内容**中真的发生（不能只停留在描述）。

- 不允许：列出 5 个客群痛点，5 个产品卖点，但活动里只有 logo 露出和 KOL 投放
- 期望：每个痛点 → 对应卖点 → 在哪个活动 / 哪条内容里被演绎/证明

呈现形式自由——可以是一张表，可以是叙事段落，可以是一组场景剧本。**形式不重要，闭环必须在。**

### Quality 3 · 传播具象化 (Concrete Communication Surfaces)

"传播策略"那一章不能停在"小红书 KOC + 抖音同城 + 微博话题"的颗粒度。必须给到**评审能想象出实际效果**的颗粒。**升级标准（every major communication phase 必须四件套都有）**：

- **完整文章标题示例 ≥5 条 / 主要传播阶段**——成稿颗粒，形如《二孩家庭换车记：从开两辆车到一台 X，终于实现全家出行自由》《放弃 BBA 换 X，为了家庭我选了真全尺寸，真香现场》。**不允许只给"关键词候选 / 话题片段 / 短句"**（如"车展看了 181 台车，最后我决定不等了"这种 = fail）；
- **≥1 条完整内容脚本骨架**（开场 / 钩子 / 转折 / 收尾），每段 1-2 句具体描述；
- **≥1 个具体话题词**（带 #），不是"#家庭出行 #安心选车"这种泛泛主题词，要有钩子（如 #181 台车我只记住了它#）；
- **≥3 类圈层 KOL/KOC 分组**——按圈层切分（如汽车 / 旅行 / 科技 / 家庭 / 亲子 等），每圈层附 1 句"内容方向 + 想被记住的标签"，可点名本地代表性账号者更佳。

> **判别口径**：每一个**主要传播阶段**（如悬念期 / 揭秘期 / 上市期 / 延续期 / 长尾期，或 N-7 / N / N+3 三段）都必须独立满足上面四件套。整案只在某一阶段给齐、其他阶段空缺 = fail。**形式不重要，具象必须在每一阶段**。

### Quality 4 · 节奏感 (Rhythm)

无论用什么 architecture，整案必须有**起伏可感**的节奏：

- 哪一个 moment 是 hero peak（评审会"啊"的那一秒）？
- 在 hero peak 之前有没有 build-up？之后有没有 cool-down？
- 章节 / 战役 / 周次之间是否有"轻 → 重 → 轻"的呼吸？
- crazy_dose 与 safe_dose 是否合理分布在节奏中？

不允许节奏全程"平峰"——三个 S 级活动堆在同一阶段、整案没有低谷的方案，会被评审感受为"用力过猛但不知道在打什么"。

### Quality 5 · 主张可记 (One Memorable Claim)

整案必须有一个能让评审散会后还记得的句子——这是**主张可记性**。它可能是：

- 一句主标语（八字双段是一种格式，不是唯一格式）
- 一个 hero event 的名字
- 一组三段式（如"提声量 / 聚流量 / 强体验"）
- 一个隐喻（如"主场 / 归航 / 造一座桥"）
- 一句产品差异化（"全尺寸 + 高智能 + 超安全"是一种格式，不是唯一格式）

**形式自由，但必须存在一个清晰可记的中心**。

#### 隐喻下渗约束（dominant metaphor cascade）

若 Voice Decision 选择了 **dominant metaphor**（如"主场 / 归航 / 造一座桥 / 首席安全官 / 一封信"），该隐喻**不允许只挂在主 slogan 上**——必须在以下三处中**至少两处**出现变奏，才算"主张可记"真的成立：

1. **主 slogan / 中心句** — 隐喻字面或语感出现；
2. **每个 stage / battle / week / 阶段的命名** — 每个阶段名都对隐喻做一次变奏（如 "亮相主场 · 美好入境" / "登陆主场 · 全城顶流" / "占领主场 · 夯实根基" 三阶段名都在"主场"上做变奏）；不允许整案 stage 名仍是营销学通用语 "悬念期 / 揭秘期 / 上市期 / 延续期 / 长尾期" 而不引入隐喻；
3. **至少 2 个 S 级 hero event 的命名或子环节命名** — hero / 子环节的名字带有该隐喻的字面或意象延伸。

> **判别口径**：Voice Decision 声明了 dominant metaphor → 主 slogan + ≥2 个 stage 名 + ≥2 个 hero 名中合计 ≥2 处出现该隐喻字面或紧密意象延伸 = pass；只在主 slogan 出现一次 = Quality 5 fail（隐喻只挂不渗），回 Step 4 把 stage 名 / hero 名做变奏。
>
> **反例**：Voice Decision 声明 metaphor = "首席安全官"，但五阶段名仍叫 "悬念期 / 揭秘期 / 上市期 / 延续期 / 长尾期"，hero 名只有 1 个 "首席安全官认证日" → fail。
>
> **正例**：metaphor = "主场"，stage 名 "亮相主场 / 登陆主场 / 占领主场"，hero 名 "家的舞台秀场 / 奕境主场私享会 / 江城主场体验" → pass。

### Quality 6 · 不端着 (No Corporate-PR Tone)

避免所有"赋能 / 强势 / 引领 / 重新定义 / 颠覆 / 全力打造 / 全方位覆盖"等空 PR 套话。这些词在标题里是 fail，在正文里是减分。

代替的是：

- 具体动词（"把 …… 搬到 ……"、"让 …… 在 …… 那一秒发生"）
- 具体宾语（"6 口人 28 寸行李箱"、"晚高峰二环"、"高考结束第三天"）
- 具体反差（"放弃 X 选 Y"、"从 N 到 1"、"以为 …… 其实 ……"）

### Quality 7 · 评审视角 (Evaluator's Lens)

写每一段时要持续问一个问题："**这一段在帮评审打哪一分？**"

- 招标方案：每段都应该能映射到 `{artifact_root}/00-rubric-binding.md` 的一个或多个维度。
- 内部方案：每段都应该能映射到 `intake.business_goal` 或 `intake.success_metric`。

不允许"为写而写"的内容。如果一段无法说清在打哪一分 / 服哪一目标——它该被删掉或重写。

### Quality 8 · 自洽气质 (Coherent Atmosphere)

整案的语气、用词、视觉关键词、活动调性应当**互相不打架**。常见三大不自洽症：

- 文案端着、活动接地气，或反之
- 主标语文学、子标语数字派
- 上半像 4A、下半像电商拼多多

如果出现两段情绪极性不一致，要么改其一，要么主动写一句过渡解释为什么本案需要这种"反差"——**主动解释**让它成为风格选择，**不解释**让它成为漏洞。

### Quality 9 · 行文流畅 (Chinese Fluency Self-Check)

长 proposal 生成时（尤其单个 hero ≥150 行 / 全案数万字时），AI 容易因 token 漂移或局部生成断片而留下三类**语病**——这些 fail 不在结构契约里却最伤评审第一印象。Quality 9 把这道收口检查显式纳入 Voice Audit。

#### 三类必扫语病

1. **短语重复粘连**：同一限定词或同一名词在 ≤10 字内连续出现，造成机械感。
   - 反例："双段双段"、"三个场景化场景化场景"、"金色「首席安全官」金色徽章"、"在北京最容易出片的地方之一，适合做仪式感活动" / "副驾的副驾"、"延续延伸"
   - 正例："金色徽章"或"「首席安全官」徽章"——同一名词不在 ≤10 字内重复。

2. **句子主谓错位 / 并列残缺**：列举句各项语法成分不齐，或主语 / 谓语缺失。
   - 反例："我的安全驾驶第二办公室、我的第三个会客厅"——前项"安全驾驶第二办公室"不通顺，与后项"第三个会客厅"并列时语法不齐。
   - 正例："我的第二个办公室、我的第三个会客厅"——并列项语法对齐、序号清晰。

3. **碎裂语义**：上下文无法解读为完整意思，或词语搭配自相矛盾。
   - 反例："在北晚高堵到公司"（应为"在北京晚高峰堵到公司"）；"最不硬的车" / "最不营销的车"（"最不 X" + 褒义词搭配错位，无法解读为夸赞）；"高考考点外最酷的营销，不是矿泉水和最不营销"（语义破碎、连读不通）。
   - 正例："不打硬广，只送水"——一句话两段对比，意思清晰。

#### Quality 9 自检流程

写完 04-proposal.md draft 后，按以下顺序扫一遍：

1. **短语级抽样**：每个 ≥800 字的章节随机抽 3 段，朗读一遍，凡需要回头才能解读的句子 = 候选语病；
2. **重复粘连检测**：肉眼或 grep 检测 ≤10 字窗口内的同字 / 同词重复（如"X X"模式）；
3. **并列项对齐检查**：每处用顿号 / 逗号 / "和" 连接的并列项，检查每项的核心结构是否一致；
4. **歧义复述**：对每个长句尝试用 1 句话复述其意思，若复述不出 = 碎裂语义。

#### Quality 9 判别口径

- 一份 04-proposal.md 出现 ≥3 处上述语病 = Quality 9 fail，回 Step 4 当段重写；
- 单个 S 级 hero 内出现 ≥2 处语病 = 该 hero 单独 fail，回 Step 4.5 当场修；
- Voice Audit 中必须显式记录"Q9 行文流畅: pass / fail"，不允许跳过。

## Voice Decision (recorded at top of `{artifact_root}/04-proposal.md`)

After Architecture Decision (in `./proposal-template.md`), make a Voice Decision and record it:

```markdown
## Voice Decision (50-150 words)
- Tone: <端着 / 不端着 / 文学 / 数据派 / 接地气 / 反差幽默 / ...>
- Slogan rhythm: <用什么字数 / 几段 / 押韵 vs 不押 / 一句 vs 三段式 / ...>
- Dominant metaphor or center claim: <一句话写出来>
- Visual key (告诉设计师): <2-3 段描述：色 + 字 + 镜头感 + 风格关键词>
- What this voice is NOT: <一两句反向定义，避免 voice drift>
```

## Surface Mechanics — Available Tools (use as needed, not all)

These are common surface techniques. **Pick the ones that serve the chosen voice; don't use all of them.**

| Tool | When useful | When wrong |
|---|---|---|
| 双层页眉（品牌联署 + 章副标） | 招标方案、央企调性、需要快速识别"这是哪一页" | 文学/慢综艺调性、节奏先行型 |
| 章扉页大开大合 | 章节多 (≥5)、严肃感强、需要呼吸节拍 | 章节少 (≤3)、希望紧凑读完 |
| 八字双段主标语 | 央企/家庭/温情系；需要朗朗上口 | 数据派 / 反讽派 / 隐喻派可不用 |
| 三段式核心策略 | 当本案确实有三个并行抓手时 | 当核心抓手是 1 个或 4+ 个时不要硬凑 |
| MAP 总览大表 (3×N) | 评审需要 5 秒读完整案时 | 已有强 hero idea 引领的 D 模式可不需要 |
| 客群三档分类 | 客群确实可分 3 档时 | 单一 niche 客群、或客群是连续谱时不要硬切 |
| SWOT 四象限 | 竞争分析适合二乘二切分时 | 竞争分析的核心矛盾是单维时不需要硬凑 |
| 痛点-卖点对应表 | 产品卖点多、需要清晰映射时 | 产品就一个核心、整案围绕它时可走叙事 |
| 传播标题清单 | 内容创作量大时 | 体验型 launch（线下为主）可减少 |
| 视觉注解 [VISUAL: ...] 块 | 关键页（hero、主视觉、舞台）需要给设计师抓 | 普通章节内文不需要每页都加 |
| 阶段四要素卡 | S 级活动需要展开到能签合同的颗粒 | A/B 级不要硬凑四要素，会显累赘 |
| 章末小结 / 营销回顾 | 章节较长、信息量大时 | 短章 / 紧凑型方案不需要 |
| **Hero 多页展开法** (按 `proposal-template.md` 的 `## Hero Event Expansion Pattern` 五模块) | **全案 ≥1 个 S 级 hero event 时（强制必选）**——单个 hero 展开为场地 + 子环节 ×3-4 + 集客 + 传播阶段化 + KPI，markdown ≥150 行 | 全案纯 A/B 短打型、无 S 级时 |
| **阶段 MAP 一页** (按 `proposal-template.md` 的 `## Stage MAP Pattern` 6 列结构) | **stage / battle / week chunk ≥3 时（强制必选）**——节奏 × 区域 × 终端 × 传播 × 内容 × 渠道一表读完 | 单 stage 突击；战役兵棋式已自带战役框架时 |

> **The rule:** Each surface mechanic is a tool with a use-case. Bringing all of them into one deck = template-党. Bringing none = chaos. Bringing 4-7 of them deliberately picked to fit the voice = expert taste. **强制必选规则**：含 ≥1 个 S 级 hero event 时，`Hero 多页展开法` 必选；stage / battle / week chunk ≥3 时，`阶段 MAP 一页` 必选。强制项不计入 4-7 的菜单数（即两件强制项 + 4-7 件自由选 = 实际可达 6-9 件，仍非"全选 = 党"）。

## Surface Mechanic 兑现约束（promise → delivery）

Voice Decision 里勾选的 surface mechanic **必须在正文真兑现**——勾了即合同，不允许"勾了但没落地"或"落地形式与勾选名字不符"。这是防止 Voice Decision 沦为装饰列表的硬约束。

### 兑现判别表

| 勾选的 mechanic | 正文必须呈现的兑现形式 | 反例（视为 fail） |
|---|---|---|
| 双层页眉（品牌联署 + 章副标） | 章节标题区 ≥80% 页面有两层标题：上层品牌联署（如"华为 ×{brand}"）+ 下层章副标（如"市场洞察"） | 全文 markdown 只有一层 `##` 标题 |
| 章扉页大开大合 | 每章开头有独立扉页段落（≥2 行，含中英文 / 数字编号 / 副标语 / 章节描述），不与正文段落连写 | 章节直接进入数据表 |
| 八字双段主标语 | 主 slogan 真是 8 字 × 2 段（如"奕家主场·境享美好" / "登陆主场·全城顶流"），上下两段对仗或押韵 | slogan 是"奕境 DH1 · 首席安全官 / 在北京守护全家人的每一次出行"——前段 ≠ 8 字、双段不对仗 → fail |
| 三段式核心策略 | 核心策略章节真分 3 段并列展开（如"声量 / 流量 / 转化"或"提声量 / 聚流量 / 强体验"），每段 ≥1 段落支撑 | 核心策略章分了 5 段或 2 段 |
| MAP 总览大表（3×N） | 至少 1 张 ≥3 列 × ≥N 行的总览大表（如三阶段 × 区域 / 终端 / 传播 / 内容 / 渠道） | 只有零散文字描述无大表 |
| 客群三档分类 | 客群章真切分为 3 个并列档（如核心 / 次核心 / 机会），每档含画像 + 占比 + 语录 | 客群一通混写 |
| SWOT 四象限 | 真正出现 2×2 SWOT 矩阵（优 / 劣 / 机 / 威），每象限 ≥3 条 | 只列优势没列劣势 |
| 痛点-卖点对应表 | 真出现 2 列对应表（痛点 → 卖点），每行 1 痛点 1 卖点 1 活动证明 | 痛点列在一段、卖点列在另一段，不对应 |
| 传播标题清单 | 每主要传播阶段 ≥5 条**成稿标题**（《……记：从…到…》），不是关键词列表 | 全是"#家庭 #智驾"短词 |
| 视觉注解 [VISUAL: ...] 块 | 关键页（封面 / hero / 主视觉 / 舞台）至少 ≥3 处出现 [VISUAL: ...] 块 | 全文无 VISUAL 注解 |
| 阶段四要素卡 | 每个 S 级活动展开为四要素或五要素结构（场地 + 内容 + 集客 + 传播 + KPI） | 仅 bullet 段落带过 |
| 章末小结 / 营销回顾 | 章末或全案末有专门小结章节，浓缩 ≤200 字 | 全案无回顾 |
| Hero 多页展开法 | 每个 S 级 lead 按 `proposal-template.md` 五模块展开 + 行数 ≥150 | 仅模块 B 一段 |
| 阶段 MAP 一页 | 每个 stage 末尾有 1 张 6 列 MAP | 只有 1 张全案 MAP |

### Mechanic Fulfillment 自检流程

Voice Audit Step 8 之后，独立做一道 "Surface Mechanic 兑现自检"：

```markdown
#### Mechanic Fulfillment Check
- [ ] 双层页眉：勾了 / 未勾；勾了→正文兑现 / 未兑现
- [ ] 八字双段主标语：勾了 / 未勾；勾了→实际 slogan 是否真为 8×2
- [ ] 三段式核心策略：勾了 / 未勾；勾了→正文是否真分 3 段
- [ ] MAP 总览大表：勾了 / 未勾；勾了→是否真有 3×N 大表
- [ ] ……（按 Voice Decision 勾选项逐项核）
```

### Mechanic Fulfillment 判别口径

- 任意一项"勾了但未兑现" = Voice Drift fail，回 Step 2 重选 mechanic（要么删掉勾选，要么把正文改到符合）；
- 不允许"勾了一堆但实际只兑现 1-2 项"——这是 mechanic 列表装饰化，必须修正；
- 反过来"正文出现了某 mechanic 但 Voice Decision 没勾" = 也要在 Voice Decision 里补上勾选，保持声明 = 落地一致。

## Anti-Patterns (universal — independent of architecture)

| 形态 | 为什么 fail |
|---|---|
| 主标语 / 三段大主题逐字搬用历史方案 | 评审一眼识别 → 直接降一档 |
| 章节顺序与某个公开范例 95% 重合 | 同上 |
| 数据表后没有人话洞察 | Quality 1 fail |
