# Quality Self-Check (Review Pass)

> Items 1–24 check **upstream rigor** (atomic insight, hotspot wiring, dose mix, timeline alignment, rubric coverage, etc.) — these are universal regardless of proposal architecture.
>
> Items 25–36 check **proposal craftsmanship** as **principle-level qualities**, not surface-form artifacts. We don't ask "are there 6 chapters" or "is there a SWOT 4-column" — we ask "is the relevant information covered" and "does the voice exhibit the quality". Form is delegated to AI's judgment per brief.

| 13 | Narrative role balance | Each stage covers ≥2 different Primary Roles |
| 14 | Energy curve | Intensity follows plan; peak appears once |
| 15 | Memory anchors | S-tier and A-tier activities have explicit anchors |

| 19 | **Packaging mix** | The active pool contains both `packaging_pass: direct` AND `packaging_pass: reworked`. Zero `reworked` = distinctive ideas were filtered out, fail. |

| 22 | **Hotspot timeline alignment** | Strategy Plan's hotspot timeline places every active `HS-*` (non-衰退) and every active Lead in ≥1 window. Orphan atoms or orphan leads fail. |
| 23 | **`{target_city}` grounding distribution** | Strategy Plan's local grounding matrix covers ≥4 of 9 G-categories (`G1–G9` in `./local-grounding-pattern.md`), with concrete `{target_city}` place names from City Pack; ≥1 lead touches `G8` (suburban belt) or `G9` (signature route) when business_goal includes drive / family-getaway hooks. **No place-name is borrowed from a previous brief's city.** |

| 25 | **Architecture decision present** | `{artifact_root}/04-proposal.md` has a `## Architecture Rationale` block with: ≥2 candidates considered, one picked with explicit rationale referring to *this* brief's intake/Spine/Lead Pool (not generic), info-coverage map, sacrifice note. Missing or template-填空 fails. |
| 26 | **Voice decision present** | `{artifact_root}/04-proposal.md` has a `## Voice Decision` block with: tone label, slogan rhythm choice, dominant metaphor / center claim, visual key, anti-definition ("NOT"), and 4-7 surface mechanics deliberately picked from the Style Guide menu. Missing or "all 12 mechanics picked" (template-党) fails. |
| 27 | **Information Coverage Contract** | `## Coverage Map` block exists at proposal end. Every Info Type from `proposal-template.md`'s Coverage Contract has at least one element of *this* proposal covering it. Any uncovered Info Type fails — even if the proposal "looks" complete. |
| 28 | **Quality 1 — 人话洞察** | Every key data table / data block is followed by a one-sentence plain-Chinese insight line, quotable in a meeting room. Tables stacked back-to-back without insight prose fails. |
| 29 | **Quality 2 — 痛点闭环** | Every product 核心卖点 has at least one matched 客群痛点, and that pairing is演绎 in at least one specific activity / content piece (not just listed). Pure spec-style 卖点 stating fails. |
| 30 | **Quality 3 — 传播具象化** | **Every** major communication phase (悬念 / 揭秘 / 上市 / 延续 / 长尾，或 N-7 / N / N+3) carries **all four**: ≥5 完整文章标题示例（成稿颗粒，非关键词候选 / 短句 / 话题片段）+ ≥1 内容脚本骨架（开场 / 钩子 / 转折 / 收尾）+ ≥1 # 话题词 + ≥3 圈层 KOL/KOC 类型分组（每圈层附内容方向 + 标签）. 任一阶段缺其中任一件 = fail. Stopping at "KOL投放 + 同城话题 + 媒体扩散" granularity fails. |
| 31 | **Quality 4 — 节奏感** | The proposal exhibits a felt rhythm: a hero peak moment is identifiable; build-up before / cool-down after are present; S-tier events do not stack in the same phase. Flat-energy throughout fails. |
| 32 | **Quality 5 — 主张可记** | The proposal contains exactly one identifiable center claim (slogan / hero event / triplet / metaphor / one-line differentiation) that an evaluator could repeat after reading. Multiple competing claims OR no memorable claim fails. |
| 33 | **Quality 6 — 不端着** | Headlines and lead activity descriptions avoid "赋能 / 引领 / 重新定义 / 全力打造 / 颠覆 / 重塑" and similar empty PR verbs. ≥3 such verbs in headlines, OR a hero slogan built on such a verb, fails. |
| 34 | **Quality 7 — 评审视角** | Every chapter / battle / week / element can be mapped to either a tender dimension (when bid_or_tender) or `intake.business_goal` / `intake.success_metric`. Any element not mappable to "this is what we're scoring" fails. |
| 35 | **Quality 8 — 自洽气质** | The proposal's tone / words / activity调性 are self-consistent — OR a deliberate "反差" is explicitly named and explained at the moment of switch. Drift between sections without acknowledgment fails. |
| 36 | **Architecture originality** | (a) The element / chapter list does not match (≥80% by sequence + naming) any well-known reference deck (e.g., past tender public submissions). (b) Main slogan / 三段式 / hero event name is not a verbatim copy of any historic / competitor / public-deck phrase. (c) Surface mechanics promised in Voice Decision are actually used (no over-use beyond 8). All three sub-checks must pass. |
| 37 | **Hero Event Expansion Depth** | 每个 S 级 lead 在 `{artifact_root}/04-proposal.md` 中按 `./shared/proposal-template.md` 的 `## Hero Event Expansion Pattern` 五模块完整展开：模块 A 候选场地 ≥2 + LAYOUT + 视觉关键词 + **City Pack 引用 (≥2 G 类具体地名 + ≥1 cultural_hook)**；模块 B 子环节 ≥3（赛道 / 篇章 / Step / Part 四选一）+ **全案 ≥3 个 S 级时 ≥2 种分解法交错**，每个子环节含名称 + 玩法 + 画面；模块 C 客流 / 留资 / 异业三件套至少 2 件具体动作；模块 D N-7 / N / N+3 三段，每段 ≥3 条成稿标题 + 渠道矩阵；模块 E 留资链路 ≥4 步 + 预算区间 + KPI 五维度。markdown 行数 ≥150 / 等价 PPT 6-10 页颗粒。任一模块缺位 / 行数不足 / 本地饱和不足 / 分解法单调 = fail。 |
| 38 | **Stage MAP Presence** | 每个 stage / battle / week chunk 末尾必须有 1 张 `## Stage MAP Pattern` MAP 总览大表，含 ≥6 列（节奏目标 / 区域动作 / 终端动作 / 传播动作 / 传播内容示意 / 传播渠道矩阵），且"传播内容示意"列引用至少 1 条该 stage 内 hero event 模块 D 的成稿标题，MAP 周边附 ≤30 字"主轴 / 总打法"概括。任一 stage 缺 MAP / 列数不足 / 内容引用编造 = fail。 |

## Self-Audit File 分离规则（mandatory）

以下自检报告**必须**输出到 `{artifact_root}/04a-self-audit.md`（独立文件），**不得**写入 `{artifact_root}/04-proposal.md`：

| 自检产物 | 出处 | 为什么不能塞进 proposal |
|---|---|---|
| Coverage Map（信息覆盖契约审计） | proposal-assembly Step 5 | 评审看不下也不需要，是项目内部 review 凭证 |
| Voice Audit（语调一致性自检 / Q1-Q9 自评） | proposal-assembly Step 8 | 同上 |
| Architecture Originality Audit | proposal-assembly Step 9 | 写入正文 = "我没抄" 的自我表扬，反而招黑 |
| Hero Expansion Self-Check（每个 S 级活动 7 项打勾清单） | proposal-assembly Step 4.5 | 内部 QA 工件 |
| Stage MAP Self-Check | proposal-assembly Step 4.6 | 同上 |
| Mechanic Fulfillment Check | proposal-assembly Step 8 后 | 同上 |
| Rubric-Surface Map（招标场景） | proposal-assembly Step 7 | **可保留**在 proposal 末尾——这是给评审看打分对应表，是合规要求；其余自检均搬走 |
| Voice & Local Saturation Pass 报告（Step 4.7） | proposal-assembly Step 4.7 | 内部收口审计，不入 proposal |

`04-proposal.md` 是**给评审看的成品**，应只含决策成果（Architecture Rationale / Voice Decision / 目录 / 各章正文 / 全案预算总表 / Rubric-Surface Map [当 bid_or_tender 时]）；自检表是**给项目内部 review 用**的工作产物。

#### 监测口径

- Review Pass 时若 `04-proposal.md` 含 ≥1 个上述自检表（`## Coverage Map` / `## Voice Audit` / `## Architecture Originality Audit` / `Hero Expansion Self-Check` 等区块标题）= 触发 Self-Audit Bleed fail，要求迁移到 `04a-self-audit.md`，再次 Review；
- `04a-self-audit.md` 必须存在，缺失 = 自检未执行，回 proposal-assembly Step 5-9 重做；
- `Rubric-Surface Map` 是**唯一例外**——招标场景下保留在 `04-proposal.md` 末尾，因为评审需要看到打分表对应；其余统统搬走。
